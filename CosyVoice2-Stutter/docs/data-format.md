# 数据格式与标签

示例均位于 `recipes/sample_data/`，内容为人工编写，音频路径仅表示格式。

## 口吃分段标注

`data/Annotation/speaker_demo.txt` 中每行：

```text
0.0<TAB>2.0<TAB>今<rep>今天</rep>天气很好。
2.1<TAB>4.0<TAB>我<fill>嗯</fill>想去公园。
```

实际文件使用制表符，不是字面字符串 `<TAB>`。对应长录音可为
`data/Audio/speaker_demo.wav`。嵌套标注目录会使用第一级目录名识别说话人；
扁平目录则使用标注文件名，不含扩展名。录音文件名应与该说话人 ID 匹配。

分段时间单位为秒，结束时间必须大于开始时间。训练脚本使用 ffmpeg 将长录音
切为单声道 24 kHz WAV，已存在的分段会复用；更改标注后应使用新的 work_dir。

## 正常语音清单

Instruct 脚本需要两列：`音频路径<TAB>纯文字`。相对路径按 AISHELL-3 根目录、
其父目录和仓库根目录依次尝试解析。

**不能直接假定所有官方 AISHELL-3 content.txt 格式都能原样使用。**
若文件内容是汉字与拼音交替排列，应先提取纯汉字转录，避免把拼音作为训练文本。
请将处理好的清单通过 `--aishell3_content` 传入。

## AISHELL 风格合成输入

```text
AISHELL-1/wav/train/S_DEMO/utt001.wav<TAB>今[今天]天气很好
AISHELL-1/wav/train/S_DEMO/utt002.wav<TAB>我嗯/i想去公园
```

脚本从 WAV 的父目录名推断说话人 ID。音频须按说话人分目录；不要将不同说话人
放在同一父目录。默认只取文件开头 50,000 条非空记录，保持输入顺序。
输入数量不足会报错，不会悄悄缩小任务。

| 输入 | 转换后 |
| --- | --- |
| `市/b` | `市[block]` |
| `纷/r` | `纷[phone_rep]` |
| `的/p` | `<prolong>的</prolong>` |
| `嗯/i` | `<fill>嗯</fill>` |
| `其中[其中]` | `其中<rep>其中</rep>` |
| `个/r/p` | `<prolong>个</prolong>[phone_rep]` |

`/p` 修饰前一个字符/文本单元；`/i` 当前只支持代码列出的单字填充词，
遇到未知格式会报错。方括号重复片段支持递归转换。此入口期望原始斜线/方括号标注，
不要把已经转换好的 `[block]` 再当作输入，否则它会被识别为重复片段。
当前沿用转换器的 `*` 过滤规则；其他来源的标注需先确认语义再接入。

## 两层指令与词表

Fine-grained 微调直接学习目标文本内的事件标签，不额外提供模式 instruct 字段。
Instruct 微调另外写入以下句级模式指令，同时保留口吃目标文本内的事件标签。


- 正常语音指令：`<|normal|><|endofprompt|>`
- 口吃语音指令：`<|stutter|><|endofprompt|>`
- 事件标签放在目标文本中，指令通过独立参数传入。
- 无 severity 控制训练或构音障碍配方。

分词器保留历史的末尾 `<|dysarthria|>` token，仅用于已有词表/权重兼容。
不能把 token 删除、重排后直接声称旧 checkpoint 仍完全兼容。
